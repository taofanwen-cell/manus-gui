## 2. 设计决策（按此执行，偏离需先说明理由）

1. **扫描走子进程，不走库内 import**：`/api/scan` 用 `subprocess.Popen([sys.executable, "scripts/ecommerce_brand_compare.py", "--brands", ...])`。
   理由：脚本含 playwright/CDP 全局状态，进程隔离崩溃不连累 API；且保持"脚本可独立用"的现有用法。
2. **单飞锁（single-flight）**：同一时刻只允许一个扫描任务，重复请求返回 409 + 当前任务状态。防风控也防并发写坏 data/。
3. **关键词与品牌概念合一**：对外统一叫 keyword。`FileHTMLSource` 解析顺序改为
   **精确文件名匹配 `pdd_raw_<keyword>_*.html` → 已知品牌反推 → 后缀剥离**。
   扫描时若 keyword 本身含"耳机"等后缀类词，`--suffix ""` 直传，避免 "蓝牙音箱蓝牙耳机" 这种拼接事故。
4. **失败要响**：请求的品牌全部无数据时 API 仍返回 200 + `rows: []` + warnings（向后兼容），
   但前端必须渲染成显式错误卡片："X 无缓存数据 → [立即扫描]"。部分失败在报告顶部放黄色警告条。
5. **登录态失效要能认出来**：扫描返回 0 商品 ≠ 数据为空，大概率是 CDP Chrome 里拼多多登录态过期。
   状态接口要把 `failed` 品牌与原因透出，前端提示"请在 CDP Chrome 窗口里重新登录后重试"。

## 5. 已知坑（前会话踩过，别再踩）

- CI 必须 `python -m pytest`，裸 pytest 缺 sys.path 会 `ModuleNotFoundError: app`
- requirements-ecommerce.txt 是 CI 依赖源，新增第三方 import 要同步补
- Git Bash 下 curl 探活有 exit 23 问题 → 探活用 python urllib（demo.sh 先例）
- Windows 子进程用 `sys.executable`（venv python），裸 `python` 会打到系统解释器
- 长任务别阻塞事件循环：Popen + 状态轮询，不要在 handler 里 `.wait()`
